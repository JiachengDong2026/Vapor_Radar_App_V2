# EPSILON PPS 校准与 DM422 整机集成（2026-10-27）

本修订基于当前 V2 工作树，保留双 LC UART、双 AD4630、HMP+AI8 共享 CON19 的已验证路径。模块 ID：TIME `0x00020200`，MOTOR `0x00470200`。新增和改变的接口以本文为准，旧原型电机页的高频/可变脉宽/可翻转 EN 极性不再适用。修改先在 `E:/Documents/Vapor_Lc_App_Test/gnss_motor_20261027_01/repo` 验证。

## 1. EPSILON 接线

| GPIO DB9-3 pin5 / 主航插 pin1 GND | CON22 SMA 外壳 | 同步信号参考地 |

MAIN 使用已验证的 921600/8N1。GPIO DB9 外形不表示 RS232 电平。手册 PDF 第25页（印刷页26，表10）确认 GPIO 输出低0–0.3V、高4.8–5V、输出电流5mA；第56页说明 GPIO1 默认连接内部 GNSS PPS，因此外部使用 GPIO2，设置 1PPS Output 并按厂家流程保存。未自动向实际设备发送配置命令。

CON22 经 R157 10Ω、U24 SN74LVC1T45（A侧5V、B侧1.8V，A→B）到 FPGA AP18，板上已完成电平转换。使用高阻输入，不加50Ω并联终端。不得将5V PPS直接接 FPGA GPIO。不要将航插 pin7 名为 SYNC 的信号未经确认就当作 PPS 输出。接线依据原理图第34页与第7页；完整旧分析见 `GNSS_WMS_DLIA_SYNC_PLAN_20261019.md`。

## 2. 校时行为与精度边界

采集帧仍用100MHz本地64位单调 tick。PPS 不清零、不跳变时间计数，不改变 ADC/DAC 或 WMS 采样频率。输入经两级 ASYNC_REG 后捕获选定沿，默认上升沿，支持原 `0x1024` 切换下降沿；应现场确认 PPS 有效沿与厂家定义。

连续三个间隔在 nominal±1% 内才置频率校准有效（即至少四个 PPS）。`ticks_per_second` 是最近一个合格间隔的实测 tick 数。它可校正本地晶振的频率偏差；±1% 是拒收门限，不是精度承诺。短毛刺、漏秒导致的异常间隔立即撤销校准和 UTC 锚点；PPS 默认超时2秒、时钟故障、禁用/软复位、改变沿/超时配置均撤销资格。连续合格 PPS 可重新获得频率资格，但必须重新确认 UTC 锚点。

必须区分“捕获了近期沿”（旧 `sync_valid`）、“PPS周期合格”（新增bit0）和“UTC历元确认”（新增bit1）。既有数据流的 time_sync flag 仍表示旧沿新鲜度，不能据此宣称绝对 UTC 有效。

手册要求同时使用串口包和1PPS，但当前查到的资料没有明确：报文时间字段对应哪个外部 PPS、传输延迟上限、失锁/闰秒时的输出语义。因此不能简单取最新串口 UTC 并取整后自动附到 PPS。本版保留串口最新时间诊断，**只有主机明确确认 PPS 序号与 UTC 整秒对应关系后才允许 UTC 锚点**。确认需依据厂家说明或现场 PPS/报文时间联合测量，不能用电脑系统时钟猜测。该确认环节尚未进行实物验收。

有有效锚点时，连续合格 PPS 的 UTC 每次增加1,000,000us；串口时间有效信息到达超时门槛时立即撤销 UTC 锚点，紧接着恢复串口 tag 也不能重新激活旧锚点；恰在门槛同拍收到新 tag 时保守地要求重新确认锚点。此实现不验证报文 UTC 与已锚定秒的数值一致性，不自行处理闰秒或厂家时间跳变；上述情况主机应撤销并重新建立锚点。映射可在主机按相邻 PPS 分段计算：

`UTC_us(T) = UTC_us(PPS) + (T - tick(PPS)) × 1,000,000 / ticks_per_second`

对已记录数据，优先用前后两个合格 PPS 包围的实测间隔作插值；对当前数据使用最近一个合格间隔作短期外推。只有校准和 UTC 有效位均成立时才能标记绝对时间有效。工具 `host/gnss_motor_control.py` 提供 Decimal 换算，避免大历元浮点损失。时钟故障期间 tick 暂停，不允许跨故障做连续 UTC 插值。

100MHz 对应10ns分辨率；两级同步引入约数个周期固定延迟及约一个周期量化不确定度，另有电平转换、线缆和 PPS 源误差。未标定这些延迟，不能将手册50ns时间精度直接当作整机实测精度。

| 1064 | RO | 不合格间隔累计数（POR清零） |
| 1068 | RO | nominal clock Hz，100000000 |
| 1070 | RW全字 | 待提交 UTC Unix整秒，>=946684800 |
| 1074 | RW全字 | 待关联的当前 PPS 序号 |
| 1078 | WO全字 | 1提交；2撤销；读为0 |

状态bit0频率合格，bit1 UTC锚点且串口tag未过期，bit2 PPS沿新鲜，bit3串口最新tag新鲜，bits10:8连续合格间隔数（饱和3）。先读1044，再读1048..1060；其间不要重复触发1044，多个主机须串行访问。1078提交必须时钟正常、已使能、PPS合格、新鲜串口时间有效、序号仍等于当前PPS，且不与新沿同拍；否则报范围错误7，不改原锚点。主机遇到序号竞态应重新取得记录，不能盲重试旧UTC。

旧1038/103C/1040保留最新串口UTC诊断和主机写入功能，它们本身不证明历元关系。旧1201同步事件32字节格式不变；未经锚定时其GNSS tag为0且valid=0；锚点提交后的下一次合格PPS才输出确认的整秒UTC。原事件的valid字段语义从“最近有tag”收紧为“已确认PPS UTC”。

## 3. 电机接线及核心来源

2026-11-10 当前装配方向补记：电机驱动45°反射镜，向上接入光路、向下移出光路。用户确认 +2000 脉冲试动使镜子明显向上移动，因此正目标 / DIR=0 为上移接入方向，负目标 / DIR=1 为下移移出方向（当前装配反向尚待单独实测）。这不代表已完全接入或移出；端点和总行程尚未标定。详见 `MOTOR_PANEL_20261110.md`。此记录补充下文原版验收状态，未改变协议或极性。

原样复用交接包 `DM422_交接包_20261027/source/fpga/rtl/motor/dm422_pc_ctrl.v`（SHA256记录在测试报告）。保持其有限运动和失联行为，只在 `stepper_ctrl.v` 适配整机100MHz、USB配置页和事件接口。原独立top/VIO不并入整机；原 `DM422_Control.exe` 会加载独立镜像替换整机固件，不用于此版。

| 板卡 | ZP_3.3T5NI08A同相转换 | DM422 |
|---|---|---|
| CON11-9 / AM11 | X1→Y1 | PUL+ |
| CON11-11 / AN11 | X2→Y2 | DIR+ |
| CON11-10 / AK12 | X3→Y3 | EN+ |
| **CON21-4 GND** | 0V/GND及5V负极 | PUL−、DIR−、EN− |

转换模块使用5V；DM422主电源使用独立24V。CON11没有GND，CON11-12 AL12绝不能接地。EN+相对EN−约5V为禁用释放，0V为使能保持；本版上电及复位 ENA=1、PUL=0。本版没有电机机械运动验收记录。

沿用交接拨码1600脉冲/转、导程4mm，即400脉冲/mm。单次1..400脉冲，20..400Hz，默认40脉冲、100Hz，对应0.10mm、0.25mm/s。频率用half_period向上取整保证不超过请求；高低各相同半周期，DIR/使能建立等待10ms。单次参数锁存，忙时拒绝修改。没有加减速、编码器、限位输入和自动回零；软件position只表示完整输出脉冲累计，不是机械测量位置。

正常STOP完成当前高脉冲、停止后保持使能；完成也保持使能。禁用、全局关闭或心跳过期可截断高脉冲并立即释放，此时物理位置可能不确定。两秒无真实主机心跳时锁定fault，之后仅恢复心跳不会使能，必须主机显式disable后再enable。全局关闭也清除本模块enable，恢复全局开关不会自动使能，不重放未完成运动。

原核心状态：bit0实际使能、bit1 busy、bit2 done、bit3 watchdog fault、bit4 range_error、bit5 alive、bit6方向、bit7 stopped、bits23:8本次完整脉冲数、bits26:24状态机。新模块不会从只读轮询自动产生心跳；主机应每≤250ms写6738=1，禁止后台“假心跳”掩盖主机失联。

原 MOTOR_CTRL（命令12/source47）子操作1/2/3/4保留，子操作5新增heartbeat（其余参数为0）。MOVE不自动替主机发心跳；未建立alive/enable时返回NOT_READY=11。要先送heartbeat，再enable；状态位/错误码沿用配置总线规则。stepper不再接受0目标和大于400的长距离动作，旧主机须按ID适配。

## 4. USB工具与首次使用

可用现有 `VaporUsbBridge.exe`/CyUSB.dll；源码在 `host/qt_monitor/bridge`，构建方法见同目录文档。Python脚本只用标准库，默认status只读；关闭其他占用FX3的上位机再使用。示例（PowerShell）：

```powershell
python host/gnss_motor_control.py --bridge E:/Documents/Vapor_Lc_App_Test/qt_formal_sync_20261011/dist/VaporUsbBridge.exe status
# 完成接线/释放电平和机械余量确认后，由操作者显式执行有限运动：
python host/gnss_motor_control.py --bridge E:/Documents/Vapor_Lc_App_Test/qt_formal_sync_20261011/dist/VaporUsbBridge.exe move --steps 40 --hz 100
# 反向40脉冲使用 --steps -40。脚本正常完成或异常退出均尝试disable。
# epoch必须已由厂家语义或测量确认；下面数字仅说明命令格式：
python host/gnss_motor_control.py --bridge E:/Documents/Vapor_Lc_App_Test/qt_formal_sync_20261011/dist/VaporUsbBridge.exe anchor --seq 123 --utc-seconds 1793100000
```

脚本有ACK/CRC/版本校验，不自动重试运动命令；进程挂起时FPGA两秒失联保护仍生效。move工具会设置全局enable（其他模块应已禁用），最后只disable电机。电机STOP/完成在RTL中保持使能，工具额外在退出时释放。工具不下载镜像、刷Flash或发送EPSILON配置。
