# 两路 TEC103 GPIO UART 接入，2026-11-15

## 已验证的实物和接线

现场两路 TTL UART 都响应温控身份查询。FPGA 的 LC0/LC1 是原始串口桥名称，其 ID_VERSION 只证明桥接口存在，不能替代实体仪表身份。上位机中的通道1/原位和通道2/遥测分别对应两台物理模块；不能当作一台设备内部的 TC1/TC2。

| 实物位置 | FPGA source / page / bridge ID | FPGA TX → 模块 RX | 模块 TX → FPGA RX |
|---|---|---|---|
| 原位温控，LC0桥 | 0048 / 6800 / 00480100 | CON11-5 / GPIO_BANK88_LP3 / AM12 | CON11-7 / GPIO_BANK88_LN3 / AN12 |
| 遥测温控，LC1桥 | 0049 / 6900 / 00490100 | CON11-6 / GPIO_BANK88_LP4 / AP11 | CON11-8 / GPIO_BANK88_LN4 / AP10 |

四根IO沿用 Bank88 / LVCMOS33。CON11 不含 GND，现有共地接线须保留。撤回先前为独立第三路提出的 CON11-14/16 改线建议，不需要将这两台模块移到新针脚。AI8 保持 CON19 RS485，HC2A 保持 CON11-13/15，SDFM300 保持 CON21。

2026-11-15 的实物只读身份查询使用原 BIT `rd105_full_20261115_c`，38400/8N1。两口各发送 `TEC=?@`、`FPV=?@`，实际原始应答均为：

```text
OKTEC=103@\r\n\0OK:FPV=4370@\r\n\0
```

原始十六进制为 `4f4b5445433d313033400d0a004f4b3a4650563d34333730400d0a00`。ASCII 自报型号103、版本4370；此证据本身不证明全部 RD105 v1.3.0 寄存器、内部双通道或控制功能兼容。解析必须兼容 `OK` 后可选冒号以及完整应答后 `CRLF` 和 NUL，不能把实际 `OK:FPV` 变体误报成身份查询失败。

每口计数增量 TX=12、RX=28，drop/parity/framing 均0。查询后两桥均恢复原禁用、115200/8N1、TX/RX FIFO空；SYSTEM.global_enable 原为1且未改。4365个 VLP 帧全部解析，丢弃字节及解析错误为0。未设置仪表温度、输出使能、模式、PID、通信参数，也未恢复出厂。

## 复用桥的最小契约

上下位机已选定零RTL方案，复用现有两桥，由主机处理仪表协议。正式采样/控制命令的现场支持范围等待根会话只读协议核查结果后补充；现有身份查询证据不能当作全部控制验收。当前没有为本次接入修改 RTL、默认值、ID、寄存器、引脚约束或 BIT。

复用 [LC双路原始UART寄存器](../LC_DUAL_UART_20261027.md)，每口独立串行执行事务。以各自页为基址 B：

- `B+10`：本地 UART 波特率，禁用且空闲时写38400。
- `B+14`：本地 UART 格式，禁用且空闲时写 `00000108`（8N1）。
- `B+04`：0禁用，1启用桥；此操作只控制 FPGA 串口，不是仪表输出使能。实际收发还要求 SYSTEM.global_enable=1。
- `B+18`：完整u32、数值0..255，每次入队一个TX字节。WRITE_REG flags=0，不使用 AUTO_COMMIT。
- `B+1C`：每次读取弹出一个RX字节；bit8/9为 parity/framing 标记。不能跨此地址做通用批量快照或 MASK_WRITE。
- `B+20/24`：TX/RX FIFO数量；`B+28/2C`：累计发送/接收字节；`B+30/34/38`：丢字节、校验及帧错误计数。

桥初值115200/8N1和禁用状态保持；主机必须显式配置38400，不能把镜像中的通用桥初值当作仪表出厂参数。桥STATUS不报告物理设备在线；身份、在线、采样与设备应答校验由主机根据真实串口回复确定。桥计数和错误不可任意回写；探测后恢复配置不等于恢复全部诊断状态。

每个TX字节可封装为独立sequence/CRC的56字节 WRITE_REG，把整条仪表请求所需VLP帧拼接到一次 Bulk OUT，随后核对全部ACK。不存在已有原子批量TX寄存器；WRITE_REG count大于1会递增地址，不能用它重复写TX_DATA。逐字节等待USB ACK会放大帧内间隔，尤其不适合Modbus RTU。一次Bulk提交也不代表在任意下游背压条件下保证原子串口发送。

## 旧 CON19 RD105 实验路径

[source004A/page6A00的共享RS485契约](../../protocol/RD105_INTEGRATION_20261115.md)描述的是先前实验路径，19200/站2与本次两台GPIO温控的实物路径不同。该路径的ID和extensions.bit4不能证明这两台TTL模块在线或接入成功，也不能替代6800/6900桥身份。

现场上位机应不呈现此旧路径，保持其禁用，不向其自动轮询、提交温度或参数事务；使用现有两GPIO桥访问两台实物。本轮明确不增加固件硬禁用逻辑，现有BIT仍保留6A00实验接口。
