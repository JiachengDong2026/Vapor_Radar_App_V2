# Clock persistence extension, revision 1.2 — 2026-09-16

The operational reset still asserts immediately when the main MMCM loses LOCKED and releases only after 16 good sys/GPIF cycles. `clk_rst_mgr.rst_persistent_n` is a separate reset for system diagnostics and `time_sync_core`: POR clears it, and its first release requires 16 locked sys cycles. Later loss of LOCKED or software reset does not assert it again.

`clock_health_monitor` runs from the continuously available 25 MHz board reference, synchronizes LOCKED through two ASYNC_REG flops and increments its lifetime counter once per synchronized falling edge. Initial acquisition of LOCKED is not a fault. A low interval must span at least two reference samples to be guaranteed detected. The board reference itself must remain available; power loss/reference oscillator failure cannot be timed by this domain.

The registered Gray `counter_cdc` transfers that monotonically incrementing counter to the persistent sys domain. `system_registers.USE_EXTERNAL_CLOCK_FAULTS=1` selects `clock_fault_total`; its default 0 preserves standalone compatibility. CLOCK +0x24 reports lifetime total minus the last software-clear base, modulo 2^32. CLOCK CONTROL bit1 updates only the base, retaining a new synchronized event arriving on that same cycle. Clearing CLOCK ERROR does not clear the counter. A new external event sets CLOCK/SYSTEM error bit5, records RESET_REASON bit3 and disables global acquisition. RESET_REASON bits0/1/2 remain POR/watchdog/software. W1C cannot erase a same-cycle new fault. Restart acquisition explicitly after recovery.

`time_sync_core.CHECK_CLOCK_VALID=1` selects its `clock_valid` input, which the real top connects to the operational reset release. Timestamp increments only while that input is high and never resets on software reset or MMCM relock. While invalid, PPS validity and cached GNSS qualification clear, the previous PPS interval is not bridged across the outage, and clock-error bit5 becomes sticky. The first subsequent PPS requalifies synchronization. Timestamp counts valid 100 MHz ticks: it is nondecreasing across an outage, but cannot represent elapsed wall time while sys_clk is absent. POR still starts a new time epoch at zero. The default parameter 0 preserves prior standalone callers.

Reset scope clarification (latest owner decision): only the explicit USB CONTROL bit1 request physically asserts CYUSB_RSTN. USB CONTROL bit3, global software reset and watchdog clear their selected internal groups; they do not assert an extra physical FX3 reset. GPIF readiness is a `firmware_seen` latch after a valid ready flag, not live cable/USB connection status; FIFO-full does not clear it.

Validation is `scripts/run_clock_persistence.py`, which compiles only the affected modules and five tests in `.work/clock_persistence`. The joint test injects MMCM LOCKED loss and stops the simulated sys clock while the board reference continues; it does not pretend behavioral MMCM output is an analog lock model. Final full-top routing/CDC and source-consistent integration runs must use this revision.
