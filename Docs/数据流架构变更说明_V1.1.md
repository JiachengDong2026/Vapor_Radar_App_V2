# 数据流架构变更说明 V1.1

## 1. 变更原因

本次变更解决两个问题：

1. DILA 每个 WMS 周期输出的是两条包含大量点的谐波曲线，不适合继续与低速传感器共用“小消息”语义；
2. 多个传感器可能同时产生数据，仅靠单路 `valid/ready` 无法解决多 producer 冲突。

## 2. 新的数据流分类

- `sample_stream`：ADC 样点级内部流；
- `msg_stream`：低速传感器、状态、事件等短消息；
- `bulk_stream`：DILA 曲线、RAW ADC 周期等大块分片数据。

## 3. 多源并发机制

所有 producer 均先进入独立 FIFO：

- 七个低速传感器各自独立 msg FIFO；
- DILA0/DILA1 各自独立 bulk FIFO；
- RAW ADC0/1 各自独立深缓存；
- 系统 RESP/ERROR/STATUS 也通过独立队列进入仲裁。

`sensor_hub` 负责低速传感器 message-locked round-robin；系统 `stream_arbiter` 再进行优先级 + 同级 RR + burst cap 仲裁。

## 4. 正式仲裁优先级

- P0：RESP / ERROR / critical EVENT；
- P1：TIME_SYNC / EPSILON2 / 关键 STATUS；
- P2：普通 sensor/status；
- P3：DILA / RAW ADC bulk fragments。

同级 RR。若低优先级持续 pending，高优先级连续完成 4 个 frame 后必须让出至少一次服务机会，防止 starvation。

## 5. DILA 分片

一个 WMS 周期对应完整 H1/H2 曲线，但传输时拆成多个 fragment：

- 默认 256 点/fragment；
- 单 fragment payload <=8192 B；
- 默认每点为 `int32 H1 + int32 H2`，共 8 B；
- 同一周期所有 fragment 共享 `timestamp` 和 `cycle_id`；
- payload 携带 `fragment_index/count` 和点索引；
- 上位机按 `source_id + cycle_id + fragment_index` 重组。

## 6. 成员责任变化

责任主体不变：

- 成员1：ADC + DILA，同时负责 DILA fragmenter 和每通道 bulk FIFO；
- 成员2：WMS + DAC，无新增责任；
- 成员3：UART + 全部低速传感器，每个传感器增加独立 msg FIFO；
- 项目负责人：sensor_hub、系统 stream_arbiter、RAW bulk framer、packetizer、USB。
