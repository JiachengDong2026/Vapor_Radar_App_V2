# 3. 子任务 A：`crc16_modbus.v`

## 3.1 功能

实现 Modbus RTU CRC16：

- reflected polynomial `0xA001`；
- init `0xFFFF`；
- 输入按字节顺序更新；
- 输出与 Modbus wire order 一致（CRC low byte first）。

## 3.2 建议接口

```verilog
input  wire        sys_clk;
input  wire        rst_sys_n;
input  wire        clear;
input  wire        data_valid;
input  wire [7:0]  data_byte;
output wire [15:0] crc_value;
```

允许组合函数 + sequential wrapper，但最终 testbench 必须与官方/已知 Modbus vector 一致。

## 3.3 必测

至少 10 组已知 CRC vector；逐字节；clear；连续两帧。

# 4. 子任务 B：`modbus_rtu_master.v`

## 4.1 功能边界

这是**协议层**，不直接绑定 HMP/RD105 设备寄存器。

支持 V1.0 必要功能：

- function 0x03 read holding registers；
- function 0x10 write multiple registers；
- 可选 0x06 write single register；
- request frame 生成；
- CRC append；
- response address/function/length/CRC 检查；
- exception response；
- timeout；
- 3.5 character silence；
- 按当前 baud 动态计算 frame gap，不可写死时间。

## 4.2 与 UART 的边界

调用**项目负责人提供的公共 UART**。Modbus core 只看 byte stream：

```verilog
// TX to uart_tx
output wire       tx_byte_valid;
input  wire       tx_byte_ready;
output wire [7:0] tx_byte_data;

// RX from uart_rx
input  wire       rx_byte_valid;
output wire       rx_byte_ready;
input  wire [7:0] rx_byte_data;
input  wire       rx_byte_start_pulse;
```

## 4.3 device-command 接口冻结

```verilog
input  wire        cmd_valid;
output wire        cmd_ready;
input  wire [7:0]  cmd_slave_addr;
input  wire [7:0]  cmd_function;
input  wire [15:0] cmd_reg_addr;
input  wire [15:0] cmd_reg_count;
input  wire [31:0] cmd_write_data;
input  wire [31:0] cmd_baud_hz;

output wire        resp_valid;
input  wire        resp_ready;
output wire [7:0]  resp_status;      // 0 OK; other local/Modbus exception
output wire [15:0] resp_word_count;
output wire [31:0] resp_data0;       // V1.0 enough for common 32-bit values
output wire [31:0] resp_data1;       // optional second value
output wire        resp_first_byte_pulse;
```

如果实际实现采用 streaming response，允许增加内部端口，但对 HMP/RD105 的 wrapper 必须维持明确、文档化且固定的接口。

## 4.4 timeout/status

`resp_status` 至少区分：OK、timeout、CRC error、address mismatch、function mismatch、length error、Modbus exception、UART error。

# 5. 子任务 C：`rs485_halfduplex_ctrl.v`

## 5.1 物理对象

HMP 使用板载 RS485 半双工 PHY。

逻辑 pins：

- TX = AN16；
- RX = AM17；
- DE/RE = AN19。

外部：

- HMP pin4 RS485+ -> CON19 pin5 A；
- HMP pin2 RS485- -> CON19 pin1 B；
- HMP pin3 common -> CON19 pin3 GND。

## 5.2 功能

状态至少：

`RX_IDLE -> TX_ENABLE_GUARD -> TX_ACTIVE -> TX_DRAIN -> TURNAROUND -> RX_IDLE`

必须保证：

- DE 在第一个 TX start bit 前稳定；
- 最后一个 stop bit 真正发送完成后才能撤 DE；
- turnaround 后再接受 response；
- 时序以 baud/bit time 计算；
- 不能以“tx FIFO 空”替代“最后 stop bit 已发完”。

# 6. 子任务 D：`hmp_modbus_rs485.v`

## 6.1 串口/协议

V1.0：

- RS485 half-duplex；
- Modbus RTU；
- 19200 baud；
- 8N2；
- default address 240；
- RH register 0x0000，32-bit float；
- temperature 0x0002，32-bit float；
- pressure compensation 0x0300（可选）；
- Modbus address 0x0600。

实际型号若与上述不同，以本项目设备手册/实机为准并记录变更。

## 6.2 功能

- 周期轮询 RH/T；
- `MEAS_MASK` 控制项目；
- 可选写 pressure compensation；
- 完整 CRC/timeout；
- 第一个 response byte 到达时锁存 timestamp；
- IEEE754 float **只做字节序重组，不在 FPGA 做浮点计算**；
- 发布统一 TLV。

## 6.3 输出

- source `0x0041`；
- msg `0x1100`；
- RH 可用 type=F32 raw bits 设备扩展 tag，或若不进行浮点换算则至少 raw；
- temperature 同理；
- README 必须说明实际 TLV tag。

为提高上位机统一性，推荐：

- 标准温度 `0x0010` 只有在 FPGA 做了经过验证的固定点换算时才输出；
- 否则保留 F32 raw bits，不伪装成 fixed-point。

## 6.4 寄存器 base `0x6100`

实现开发指南全部 HMP 寄存器：BAUD、MODBUS_ADDR、SERIAL_FORMAT、POLL_INTERVAL_MS、MEAS_MASK、LAST_RH_F32_BITS、LAST_TEMP_F32_BITS、CRC/TIMEOUT counters、PRESS_COMP_F32_BITS。

# 7. 子任务 E：`rd105_uart.v`

## 7.1 物理连接

V1.0 使用 Bank88 GPIO 软件 TTL UART：

| 信号 | CON11 | FPGA ball |
|---|---:|---:|
| FPGA TX -> RD105 RX | pin5 | AM12 |
| RD105 TX -> FPGA RX | pin7 | AN12 |

**设备侧 TTL 插座具体 pin 编号仍需线束/硬件确认。** FPGA 侧已冻结；不得把可能的 5 V TTL 直接接到 FPGA。若设备不是 3.3 V compatible 必须外加 level shifter。

## 7.2 协议

V1.0 固定使用：

- TTL UART；
- 38400 8N1；
- device address 1；
- Modbus RTU；
- function 0x03 read；
- function 0x10 write；
- channel 1 register 0x1000..；
- target temperature `TG` at 0x1000，int32 两寄存器；25 °C = 25,000,000。

## 7.3 功能

必须：

- 读 target temperature；
- 读 actual temperature；
- 写 target temperature；
- 读 ERRORCODE；
- timeout/CRC；
- 写操作只有收到设备成功确认后才更新 active target；
- target 使用 shadow + commit/command 机制，不能 host 写寄存器即假定设备已生效。

## 7.4 timestamp

一次读响应的 timestamp = response first byte 时间。

## 7.5 输出

- source `0x0046`；
- msg `0x1100`；
- `target_temperature_uC` tag `0x0014`；
- `actual_temperature_uC` tag `0x0015`；
- device error 可用 `0x0002`。

## 7.6 寄存器 base `0x6600`

必须实现开发指南列出的 BAUD、DEVICE_ADDR、PROTOCOL_MODE、CHANNEL、TARGET_TEMP_UC、ACTUAL_TEMP_UC、ERRORCODE、POLL_INTERVAL_MS、CRC_ERR_COUNT、TIMEOUT_COUNT。

`PROTOCOL_MODE` V1.0 只允许 0=Modbus；写 1=ASCII 可返回 `cfg_error` 或保留但 disabled，README 明确。

# 8. 子任务 F：`i2c_master.v`

BMP390/SHT45 共享同一物理 I²C：

- SCL = CON11 pin1 = AH13；
- SDA = CON11 pin3 = AJ13；
- BMP390 INT optional = CON11 pin2 = AN13。

## 8.1 电气行为

SCL/SDA 必须 open-drain：只输出 `0` 或 `Z`，禁止主动驱动 `1`。

## 8.2 功能

- START；
- repeated START；
- STOP；
- 7-bit address；
- read/write；
- ACK/NACK；
- multi-byte；
- 100 kHz / 400 kHz；
- clock stretching（若当前器件不使用也建议可容忍）；
- timeout；
- bus stuck recovery：最多 9 个 SCL pulse + STOP；
- busy/command handshake。

## 8.3 冻结 command 接口

```verilog
input  wire        req_valid;
output wire        req_ready;
input  wire [6:0]  req_addr7;
input  wire        req_read;
input  wire [7:0]  req_reg;
input  wire        req_use_reg;
input  wire [5:0]  req_len;
input  wire [31:0] req_wdata;

output wire        rsp_valid;
input  wire        rsp_ready;
output wire [7:0]  rsp_status;
output wire [31:0] rsp_rdata;
output wire [5:0]  rsp_len;
```

若 BMP390 calibration block 超过 4 byte，允许 driver 进行多次 transaction；不要为了单次大块读取把 V1.0 接口复杂化。

共享仲裁由项目负责人 `sensor_hub` 做，因此每个 driver 对外给出独立 request；**不要在两个 driver 内直接抢同一个 inout SDA/SCL**。

# 9. 子任务 G：`bmp390_driver.v`

## 9.1 器件基线

- I²C addr 0x76/0x77；
- CHIP_ID 0x00 expected 0x60；
- raw pressure/temp starting 0x04；
- INT_STATUS 0x11；
- PWR_CTRL 0x1B；
- OSR 0x1C；
- ODR 0x1D；
- CONFIG 0x1F；
- CMD 0x7E。

## 9.2 driver 与 I2C master 的边界

`bmp390_driver` **不直接实例化物理 inout**；它向 `sensor_hub/i2c_master` 发 transaction request。建议使用第 8.3 节 command interface。

## 9.3 功能

- CHIP_ID check；
- 读取 calibration raw block 并缓存；
- PWR/OSR/ODR/IIR 配置，shadow+commit；
- 周期读取 raw pressure/temp；
- 可选 INT data-ready；
- timestamp：若用 INT，INT event 时刻；否则一次 measurement read request 发起时刻；
- 输出 raw TLV；
- init 后至少一次输出/提供 calibration data，便于 host compensation。

V1.0 **不强制 FPGA 实现 Bosch compensation floating algorithm**。默认 host compensate，避免增加不必要 fixed-point 风险。

## 9.4 source/register

- source `0x0043`；msg `0x1100`；
- base `0x6300`；
- 完整实现开发指南 BMP390 寄存器。

## 9.5 测试

- 正确/错误 CHIP_ID；
- NACK；
- calibration read；
- raw read；
- commit；
- I²C timeout；
- bus recovery 后继续；
- `m_ready` backpressure。

## 10.1 基线

- 输出 raw temperature/RH；

# 11. HMP/BMP/SHT/RD105 数据格式统一要求

四个传感器都通过 `msg_stream` 输出 `SENSOR_TLV_RECORD`：

```text
u16 schema_version = 1
u16 field_count
TLV[]
```

TLV：

```text
u16 tag
u8  type
u8  length
value[length]
pad to 4-byte boundary
```

不得让 Modbus/I²C 原始总线帧成为上层唯一数据格式；需要调试时可附带 `tag=0x0003 raw_frame`。

每个 driver 的 `docs/README.md` 必须列出其实际输出 tag/type/单位。

为避免三方联调时再次协商，V1.0 设备扩展 tag 固定如下：

| source | tag | type | 含义 |
|---|---:|---:|---|
| HMP | `0x0110` | 9/F32 | RH，设备返回的 IEEE754 raw bits，单位 %RH |
| HMP | `0x0111` | 9/F32 | Temperature，IEEE754 raw bits，单位 °C |
| HMP | `0x0112` | 9/F32 | Dew point，若启用，单位 °C |
| BMP390 | `0x0200` | 3/U32 | raw pressure，低 24 bit 有效 |
| BMP390 | `0x0201` | 3/U32 | raw temperature，低 24 bit 有效 |
| BMP390 | `0x0202` | 11/BYTES | calibration raw block |
| SHT45 | `0x0300` | 2/U16 | raw temperature word |
| SHT45 | `0x0301` | 2/U16 | raw RH word |

RD105 使用已有标准 tag `0x0014/0x0015`。如果后续需要增加字段，只能在本设备已有扩展区继续追加，并同步提升文档版本；不得改变上述 tag 含义。
