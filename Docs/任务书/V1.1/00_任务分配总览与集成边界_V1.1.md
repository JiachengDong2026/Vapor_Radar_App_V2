# 机载三维水汽激光雷达 FPGA 下位机——三成员任务分配总览与集成边界

> 版本：V1.1（取代 V1.0）  
> 开发环境：Xilinx Vivado  
> RTL：Verilog-2001  
> FPGA：Xilinx XCKU11P-2FFVA1156I  
> 项目负责人：负责系统架构、公共 UART、DILA、时间同步、项目级数据流/协议、USB3.1/FX3、顶层整合与整机验收。  
> 上位机对接人员：不承担下位机 RTL，仅依据 VLP1/寄存器协议完成 Qt 侧通信对接。

## 1. 本次调整后的最终分配

| 成员 | 正式负责内容 | 工作重点 | 不负责内容 |
|---|---|---|---|
| 成员1 | **AD4630 + ADC3660 两个 ADC**；EPSILON2 | 两种 ADC 采集架构、source-synchronous/CDC/FIFO/XDC；GNSS FDILink 解析 | DAC、WMS、UART、DILA、USB |

| 成员3 | HMP；RD105；BMP390；SHT45；Modbus RTU；RS485 半双工控制；I²C master | 低速协议栈复用、CRC、RS485 DE/RE、共享 I²C、四个 driver | ADC、DAC、WMS、UART、USB |

### 工作量平衡说明

- **成员1**模块数少，但两个 ADC 是全项目接口开发中时序和 CDC 风险最高的部分；ADC3660 还需要 lane/DDR/FCLK/DCLK 约束和板级确认，因此不再叠加普通传感器，只增加 EPSILON2 这一项协议型任务。
- **成员2**负责两路完整激光驱动输出链。WMS 不再由负责人开发，而由该成员完成，并与 AD5791 的更新能力共同验证；PTB210/TFA1500-L 都通过负责人提供的 UART 核实现，协议逻辑相对轻。
- **成员3**设备数量最多，但均为低速接口；Modbus、RS485、I²C 均可复用，四个设备 driver 共享底层模块，时序压力显著低于成员1。

## 6. 项目级统一接口

### 1. 时钟与复位

除器件源同步采样时钟外，控制平面统一使用：

```verilog
input wire sys_clk;      // 100 MHz
input wire rst_sys_n;    // 低有效，同步释放
```

任何成员不得自行再建立第二套系统时间基准或全局复位树。

### 2. `cfg_bus`

所有正式设备模块均实现：

```verilog
input  wire        cfg_valid;
input  wire        cfg_write;
input  wire [31:0] cfg_addr;
input  wire [31:0] cfg_wdata;
input  wire [3:0]  cfg_wstrb;
output wire        cfg_ready;
output wire [31:0] cfg_rdata;
output wire        cfg_error;
```

规则：

- `cfg_valid && cfg_ready` 完成一次访问；
- `cfg_error` 与 `cfg_ready` 同拍有效；
- 单 outstanding transaction；
- 仅响应自己的 0x100 B 地址页；其他地址不得拉高 `cfg_ready`；
- 非法参数、越界值和不支持写操作必须返回 `cfg_error`，不得静默接受。

### 3. ADC `sample_stream`

```verilog
output wire        s_valid;
input  wire        s_ready;
output wire [31:0] s_data;
output wire [7:0]  s_flags;
```

- `s_valid && s_ready` 表示一个样点完成传输；
- `s_valid=1 && s_ready=0` 时 `s_data/s_flags` 必须保持；
- 物理 ADC 不能被 `s_ready` 反压停采；必须先进入本地 FIFO；
- FIFO 满必须置 overflow、累计 `DROP_COUNT`，不得静默覆盖。

### 4. 低速设备 `msg_stream`

```verilog
output wire        m_valid;
input  wire        m_ready;
output wire [31:0] m_data;
output wire [3:0]  m_keep;
output wire        m_sof;
output wire        m_last;
output wire [15:0] m_source_id;
output wire [15:0] m_msg_id;
output wire [63:0] m_timestamp;
output wire [31:0] m_cycle_id;
output wire [31:0] m_flags;
```

`m_valid=1 && m_ready=0` 时上述所有输出保持稳定。

### 5. 时间输入

```verilog
input wire [63:0] timestamp_now;
input wire        time_sync_valid;
input wire [31:0] time_sync_seq;
```

成员模块只能消费该时间服务，不得自行维护全局 timestamp。

## 7. WMS 与 ADC 的项目级边界

成员2的 WMS 每路必须输出：

```verilog
output wire [31:0] dac_sample;
output wire        dac_sample_valid;
input  wire        dac_sample_ready;
output wire        scan_start;
output wire [31:0] cycle_id;
output wire [31:0] sine_phase;
```

项目负责人使用 `scan_start/cycle_id/sine_phase` 分别连接：

- `adc_cycle_framer`；
- DILA 相位参考；
- 周期级 timestamp 捕获；
- 后续 packetizer。

成员1的两个 ADC **不自行产生 WMS cycle_id**，只负责连续可靠样点输出；周期切分由项目负责人完成。

memberX_<scope>/

硬性规则：

1. `rtl/` 不得放 testbench/stub；
2. 每个模块必须可独立 elaboration；
3. `run_sim.tcl` 可在 Vivado batch 下跑完本成员全部 test；
4. `run_synth_check.tcl` 至少完成综合 sanity check；
5. XDC 只提交本成员接口 fragment，不修改总 XDC；
6. 不修改 VLP1、统一 `source_id/msg_id`、项目顶层和其他成员 RTL；
7. `known_issues.md` 无问题也必须写 `None`。

## 9. 合并准入条件

- Verilog-2001；
- testbench 全部 PASS；
- 无 latch、多驱动、未说明 CDC；
- backpressure 时输出稳定；
- ADC overflow/传感器 CRC/timeout 等错误不得静默；
- register map 与代码一致；
- XDC 引脚与硬件资料一致；
- 综合 Error=0、Critical Warning=0；新增普通 Warning 必须解释；
- 不得通过 false path 掩盖真实 ADC 输入时序问题。

## 10. 推荐并行开发顺序

- 成员1：先冻结 ADC3660 lane map，同时开发 AD4630；随后完成 ADC3660；EPSILON2 可并行写 parser。
- 成员2：先冻结 WMS 数值格式和 DAC update-rate 上限；并行完成 AD5791；随后闭环验证 WMS→DAC；PTB/TFA 可穿插完成。
- 成员3：先完成 CRC/Modbus/I²C/RS485 公共底层，再并行接入 HMP/RD105/BMP390/SHT45。
- 项目负责人：尽早提供公共 UART 可综合版本和仿真模型，使三名成员均不被串口依赖阻塞。
