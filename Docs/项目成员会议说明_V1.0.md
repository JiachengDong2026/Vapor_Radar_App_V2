# 1. 项目最终目标

本项目最终需要完成一套可实际运行的 **FPGA 下位机系统**，服务于机载水汽激光雷达，实现：

```text
传感器 / 探测器 / 执行器
        ↓
板级物理接口
        ↓
FPGA 驱动、采集、处理、时间同步与控制
        ↓
统一数据流与协议
        ↓
FX3 + USB3.1
        ↓
Qt 上位机
```

最终系统应具备以下能力：

- 两套 WMS 激励；
- 两路 DAC 激光调制输出；
- 两路 ADC 探测器信号采集；
- 双路 DILA 数字锁相与谐波曲线输出；
- 多种辅助传感器采集；
- 统一时间戳；
- 统一寄存器配置与状态管理；
- 多源数据缓存、仲裁和封包；
- USB3.1 与上位机双向通信；
- 上位机可完成参数配置、启动/停止、状态读取、数据接收、显示和存储。

**最终验收目标不是“每个模块单独能跑”，而是所有模块能够按统一接口直接集成并稳定联调。**

# 4. 项目统一数据流

为了避免不同类型数据混在一起，项目正式区分三类内部数据流。

## 4.1 `sample_stream`

用于 **ADC 样点级内部数据传输**。

用途：

```text
ADC → FIFO/CDC → DILA
ADC → RAW cycle framer
```

特点：

- 高频；
- 样点级；
- ADC 物理端不可被下游反压停采；
- 必须先缓存，再进入后续模块。

---

## 4.2 `msg_stream`

用于 **低速传感器、状态、事件等短消息**。

典型来源：

- PTB210；
- HMP；
- EPSILON2；
- TFA1500-L；
- RD105；
- BMP390；
- SHT45。

每个传感器必须先进入**自己的独立 FIFO**，不能多个传感器直接硬并在一条消息线上。

---

## 4.3 `bulk_stream`

用于 **DILA 曲线、RAW ADC 周期数据等大块数据**。

DILA 每个 WMS 周期输出两条曲线：

```text
H1[0], H2[0]
H1[1], H2[1]
...
H1[N-1], H2[N-1]
```

当前默认：

- 每个点：`int32 H1 + int32 H2`；
- 每点共 8 Byte；
- 每个 WMS 周期形成完整 DILA 曲线；
- 传输时按 fragment 分片；
- 默认最多 256 点/fragment；
- 单 fragment payload 不超过 8192 Byte；
- 同一周期所有 fragment 共用同一 `timestamp` 和 `cycle_id`。

---

# 5. 多源同时发送时如何避免冲突

多个传感器、DILA、RAW ADC 可能同时产生数据，因此系统不允许多个 producer 直接连接同一条输出流。

统一结构为：

```text
PTB      → FIFO ─┐
HMP      → FIFO ─┤
EPSILON  → FIFO ─┤
BMP390   → FIFO ─┤
SHT45    → FIFO ─┤
TFA      → FIFO ─┤
RD105    → FIFO ─┤
                 ├→ sensor_hub ─┐
DILA0 → bulk FIFO ──────────────┤
DILA1 → bulk FIFO ──────────────┤
RAW0  → bulk FIFO ──────────────┤
RAW1  → bulk FIFO ──────────────┤
RESP / ERROR / STATUS FIFO ─────┤
                                ↓
                         stream_arbiter
                                ↓
                           packetizer
                                ↓
                              USB3.1
```

## 仲裁原则

- 按**完整消息 / fragment**仲裁，不允许不同 source 的 beat 交叉；
- 同级数据源采用 Round Robin；
- 系统级采用“优先级 + RR + burst cap”；
- 当前优先级：
  - P0：RESP / ERROR / critical EVENT；
  - P1：TIME_SYNC / EPSILON2 / 关键 STATUS；
  - P2：普通 sensor/status；
  - P3：DILA / RAW ADC bulk；
- 高优先级连续服务达到上限后必须让出一次机会，防止低优先级长期饥饿。

# 6. 时间同步原则

系统统一采用一套时间基准：

- `system clock = 100 MHz`；
- `timestamp = 64 bit`；
- `10 ns/tick`；
- EPSILON2 `SYNC_IN` 接入统一 `time_sync_core`。

所有正式数据进入系统数据层时，都应能够确定：

```text
这条数据是谁产生的？
是什么类型？
什么时候产生的？
是否属于某个 WMS 周期？
数据状态是否正常？
```

因此统一使用 `source_id / msg_id / timestamp / cycle_id / flags` 等元数据。

# 9. `valid/ready` 统一握手规则

标准流接口统一采用：

```text
valid = producer 表示“我有数据”
ready = consumer 表示“我能接收”
```

只有：

```text
valid && ready == 1
```

在当前时钟沿成立时，本拍数据才算真正传输成功。

如果：

```text
valid = 1
ready = 0
```

发送端必须保持：

- data；
- keep；
- sof / last；
- metadata；

直到成功握手。

# 10. 配置与寄存器规范

涉及实时运行的配置统一采用：

```text
shadow register
      ↓
COMMIT
      ↓
safe boundary
      ↓
active register
```

禁止一个 WMS 周期执行到一半时突然修改关键参数。

模块必须只响应自己所属的寄存器地址页。

成员不得修改已冻结 base address。

核心原则：
