## 1.1 三条成员链路的设计原则

### 成员1：接收与解调链
成员1对“从 ADC 物理引脚开始，到 DILA 标准输出结束”的数据正确性负责。两种 ADC 的物理接口虽然不同，但进入系统后必须统一为 `sample_stream`。DILA0/DILA1 使用同一套可参数化 RTL，分别服务原位和遥测通道；每个 WMS 周期的曲线按 fragment 输出到独立 `bulk_stream`。

### 成员2：激励与输出链
成员2只负责 WMS + DAC，不再承担任何传感器协议。WMS 必须输出供系统使用的 `scan_start/cycle_id/sine_phase`，同时生成 DAC 样点并通过 AD5791 物理接口输出。

### 成员3：全部低速/串行传感器链
成员3统一负责公共 UART 和全部非 ADC 传感器，避免多个成员各自实现串口或协议栈。成员3需要把 RS232、RS422、RS485、TTL UART、I²C 等设备差异全部封装在驱动内部，上层只看到各设备独立的标准 `msg_stream` 和寄存器接口；每个 source 先进入独立 FIFO，再由负责人实现的 `sensor_hub` 进行消息级仲裁。

# 4. 成员之间必须冻结的接口

## 4.1 成员2 → 成员1/项目负责人：WMS参考接口

每个 WMS 通道必须提供：

```verilog
output wire        scan_start;       // 一个 sys_clk 周期脉冲，新锯齿周期开始
output wire [31:0] cycle_id;         // scan_start 时已经更新为新周期 ID
output wire [31:0] sine_phase;       // 当前 1f 相位，U32: 0..2^32-1 = 0..2pi
output wire        wms_running;
output wire        phase_valid;
```

冻结要求：

1. `scan_start`、`cycle_id`、`sine_phase` 位于 `sys_clk=100 MHz` 控制/参考域；
2. `scan_start` 仅 1 cycle；
3. `cycle_id` 每次有效 scan 起始递增 1；
4. `phase_valid=1` 时 `sine_phase` 可供 DILA 锁相；
5. WMS/DAC 内部 SPI 实现不能泄漏到成员1；
6. 成员1不得读取成员2内部寄存器来“猜”相位。

项目负责人同时消费 `scan_start/cycle_id` 用于 RAW ADC 周期切帧和周期级 timestamp。

## 4.2 成员1 → 项目负责人：ADC RAW 与 DILA 输出

每个 ADC 继续暴露标准 RAW `sample_stream`，供项目负责人 `adc_cycle_framer` 和 DILA 使用：

```verilog
output wire        raw_valid;
input  wire        raw_ready;
output wire [31:0] raw_data;
output wire [7:0]  raw_flags;
```

DILA0/DILA1 从 V1.3 起不再输出低速 `msg_stream`，而输出各自独立的 `bulk_stream`：

```verilog
output wire        b_valid;
input  wire        b_ready;
output wire [31:0] b_data;
output wire [3:0]  b_keep;
output wire        b_sof;
output wire        b_last;
output wire [15:0] b_source_id;
output wire [15:0] b_msg_id;
output wire [63:0] b_timestamp;
output wire [31:0] b_cycle_id;
output wire [31:0] b_flags;
```

冻结要求：

- `DILA0 source=0x0030`, `DILA1 source=0x0031`, `msg_id=0x1001`；
- 每个 WMS 周期可以产生多个 fragment；
- 默认最多 256 点/fragment；单 fragment payload <=8192 B；
- 每通道独立 bulk FIFO / ping-pong buffer，至少能缓存 2 个最大 fragment；
- 同一周期所有 fragment 的 timestamp/cycle_id 相同；
- 项目负责人只在 fragment 的 `b_last` 后切换 source。

成员1必须保证物理 ADC 不受下游 `ready` 直接反压。

## 4.3 成员3 → 项目负责人：传感器统一消息接口

每个 sensor driver 最终输出**独立**标准 `msg_stream`，并在 driver 输出侧配置独立消息 FIFO。项目负责人不需要知道 PTB ASCII、FDILink、Modbus、TFA binary frame 或 SHT CRC 等细节。

冻结要求：

- PTB/HMP/EPSILON2/BMP390/SHT45/TFA/RD105 不得直接并联一套 `msg_stream`；
- 每个 source 默认建议 FIFO 有效容量 >=1 KiB，至少能容纳一条最大合法记录；
- FIFO full 必须计数并置错误；
- 项目负责人实现 `sensor_hub`，按 message-locked round-robin 在各 source FIFO 之间仲裁；
- 成员3不实现项目级 `sensor_hub/stream_arbiter`。

成员3的 UART、Modbus、I²C 可以在成员内部复用。

# 6. 项目级统一接口要求

> V1.3：`sample_stream`=ADC样点；`msg_stream`=低速消息；`bulk_stream`=DILA/RAW大块分片。禁止混用。

## 6.1 时钟/复位

```verilog
input wire sys_clk;       // 100 MHz
input wire rst_sys_n;     // 低有效，同步释放
```

器件源同步时钟（ADC DCLK/FCLK 等）可在接口模块内部使用，但进入统一数据平面前必须完成 CDC。

## 6.2 `cfg_bus`

正式可配置模块统一实现：

```verilog
input  wire        cfg_valid;
input  wire        cfg_write;
input  wire [31:0] cfg_addr;
input  wire [31:0] cfg_wdata;
input  wire [3:0]  cfg_wstrb;
output wire        cfg_ready;
output wire [31:0] cfg_rdata;
output wire        cfg_error;
```

规则：

- `cfg_valid && cfg_ready` 完成一次访问；
- `cfg_error` 与 `cfg_ready` 同拍；
- 单 outstanding；
- 只响应自身地址页；
- 非法参数返回 `cfg_error`；
- 实时参数优先使用 shadow + commit；
- WMS/DILA 等实时处理参数在安全边界生效。

## 6.3 统一寄存器页首部

每个 `0x100 B` 页：

| offset | 名称 | 访问 | 含义 |
|---:|---|---|---|
| `+0x00` | `ID_VERSION` | RO | module ID/version |
| `+0x04` | `CONTROL` | RW/W1P | enable/reset/commit/clear FIFO |
| `+0x08` | `STATUS` | RO | ready/busy/online/overflow/error/time sync |
| `+0x0C` | `ERROR` | RO/W1C | timeout/protocol/overflow/config/internal/device/data format |

# 10. 统一验收门槛

每名成员交付前必须满足：

1. 所有 testbench PASS；
2. RTL 无 latch；
3. 综合无 Error/Critical Warning；
4. CDC 已解释或约束；
5. I/O 时钟有正确时序约束；
6. `cfg_bus` 非本地址不响应；
7. valid/ready 背压测试通过；
8. FIFO overflow/timeout/CRC 等异常均可观测；
9. XDC 只提交自己的 fragment；
10. 不提交 `.runs/`、`.cache/`、巨大 waveform 等临时文件；
11. 项目负责人将成员 RTL 加入顶层时，不应需要修改成员内部代码才能完成基本实例化。

# 11. 推荐并行开发顺序

### 成员1
ADC物理接口 → capture FIFO/CDC → ADC标准流 → DILA数学链 → DILA block → 双通道端到端测试。

### 成员2
WMS phase/波形 → AD5791 transport → 单通道 WMS→DAC → 双通道独立运行 → 导出冻结 WMS参考接口。

### 成员3
UART → Modbus/RS485/I²C → PTB/HMP/RD105 → EPSILON/TFA → BMP/SHT → 全传感器 `msg_stream` 回归。

三名成员均应在其他成员未完成时使用**同端口仿真 stub/model**，不得以依赖未完成为理由串行等待。
