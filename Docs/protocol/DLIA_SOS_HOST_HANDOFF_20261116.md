# DLIA 2～8 阶可编程滤波器：上位机对接规范

> 同日PPS扫描扩展：默认连续模式保持本文原行为；WMS选择PPS单次模式后，每次实际DAC扫描起点清除SOS历史和抽取状态，活动扫描中DLIA COMMIT返回BUSY，采样率不匹配时丢弃新输入并完成异常收尾。系数、阶数和截止频率上传格式不变。请同时采用[PPS—WMS—DLIA对接规范](PPS_WMS_DLIA_HOST_HANDOFF_20261116.md)，评估每次扫描的滤波建立瞬态。

日期：2026-11-16。原始开发基线：正式仓库 `7cf6986`（2026-11-13 HC2A/HCD2 归档版本）；后续合并GitHub `80f8319`，保留最新AI8/SDFM300/DM422/TEC103接口。

本功能在两路 DLIA 的混频后、抽取前执行低通滤波。每路内部 1f I/Q、2f I/Q 四个分量使用同一组系数，两路 DLIA 可以分别配置。上位机计算并量化系数，FPGA 接收完整系数银行，验证后在采集周期边界统一生效。支持整数阶数 **2、3、4、5、6、7、8**；截止频率元数据单位为整数 Hz。系数实际决定频响，FPGA 不从截止频率寄存器生成自定义系数。

本说明描述新源码接口。旧归档 `20261113_hc2a_rhfix` BIT 不包含此扩展；不能把新源码仿真或综合通过当作旧 BIT 已升级。具体验证记录见 [修订记录](../INTEGRATION_REVISION_20261116_DLIA_SOS.md)。

## 1. 职责与数据通路

```text
实际 ADC 输入采样率 Fs + 阶数 N + 截止频率 Fc
  → 上位机 Butterworth 设计 → SOS 分节、增益分配、Q2.46 量化
  → 量化后稳定性/频响检查 → VLP1 WRITE_REG
  → FPGA shadow → COMMIT 快照 → 周期边界且流水排空 → active

ADC → 参考混频 → SOS0 → SOS1 → SOS2 → SOS3 → 抽取 → 幅值/分帧
```

固定四节算术流水，每节接收四个 signed32 分量。阶数 N 启用前 `ceil(N/2)` 节；其余节按原始输入旁路，但仍经过相同流水延迟。奇数阶的一阶节必须放在最后一个启用节：`b2=a2=0`。所有未启用节的银行内容必须填单位节 `[1,0,0,0,0]`。

每一节按以下符号约定计算。参考生成器对每个活动SOS做单位直流增益归一化，量化后调整整数分子和，使 `b0+b1+b2 = 2^46+a1+a2` 精确成立；整个低通级联的直流增益为1。

```text
H(z) = (b0 + b1*z^-1 + b2*z^-2) / (1 + a1*z^-1 + a2*z^-2)
y[n] = b0*x[n] + b1*x[n-1] + b2*x[n-2] - a1*y[n-1] - a2*y[n-2]
```

`a1/a2` 是归一化分母系数原值；不要在发送前再取反。`a0` 恒为 1，不上传。上位机必须使用滤波器入口的 **ADC 实际输入采样率**，不能使用 DLIA 抽取后的输出率。下位机回读入口为 `BASE+0xFC`。本能力不扩大 AD4630 的硬件采样率范围；12.5 MS/s 是原兼容模块/仿真 profile。

## 2. 能力识别与旧主机兼容

DLIA0：BASE=`0x5000`，source=`0x0030`；DLIA1：BASE=`0x5100`，source=`0x0031`。

1. 按原协议读取模块 ID。保留 ID `0x00300101` / `0x00310101`。
2. 尝试读取 `BASE+0xF0`，必须返回 **`0x534F5301`**（SOS API v1）。旧固件可能返回未知地址错误；此时禁止上传新系数。
3. `BASE+0x24` 在内置模式保留 `0x00040101` / `0x00040102`；自定义模式为 `0x80000000 | N`，例如八阶=`0x80000008`。
4. VLP1 帧、source ID、DLIA 数据 payload 格式保留。合并最新AI8/RD105更新后系统 `HOST_EXTENSION_FLAGS=0x3B`（原SOS开发基线为0x29），SOS未新增全局能力位。新能力必须按 `+0xF0` 探测，不能只凭全局截止频率扩展 bit5 判断。

仓库现有 Qt 界面没有接入新控件，且只认可旧 profile。需要上位机开发方同步扩展 profile 白名单、写入流程和回读显示。旧主机可继续使用上电默认四阶/1 kHz 和旧七档模式；新主机不得把自定义模式显示为固定 1 kHz。

## 3. 寄存器表

全部地址以字节计、4 字节对齐。所有寄存器为 U32；系数银行按后述方式承载 signed48。读只读项、读影子项、写入 ACK 均沿用现有 VLP1 READ/WRITE_REG。

| 偏移 | 权限 | 说明 |
|---|---|---|
| `+04` | RW/pulse | CONTROL：bit0 enable，bit1 soft reset，bit2 commit，bit3 clear。commit 不得与 reset/clear 同次发出 |
| `+08` | RO | STATUS.bit2=`pending`，bit7=`any error`；其余沿用原定义 |
| `+0C` | W1C | ERROR：bit4 配置拒绝，bit6 滤波饱和，新增 bit8 自定义系数采样率失配 |
| `+20` | RW shadow | MODE：bit0 WMS参考，bit1幅值输出，bit2全滤波旁路；其余保留 |
| `+24` | RO | 当前 profile，见能力识别 |
| `+28` | RO | 数值描述 `0x20112E10`，系数46小数位、状态16小数位 |
| `+34` | W1C | 启用节饱和脉冲总数；同周期多节饱和累加。不按单个I/Q分量计数 |
| `+58` | RW shadow | 旧内置截止档位 100/250/500/1000/2000/5000/10000 Hz。写入即选择内置模式，并丢弃未提交上传标志；仍需 commit |
| `+5C` | RO | 旧内置截止档位生效值；自定义模式下不要据此显示实际截止频率 |
| `+60` | RW | 上传开始/阶数：写2～8开始新一轮上传并清空30字完整性位图；写0选择内置四阶模式。只接受完整32位写入。上电0 |
| `+64` | RO | 生效阶数，上电4 |
| `+68…+DC` | RW shadow | 30个连续系数字，120字节。每字必须完整32位写。必须先写非零 `+60` 才允许写入；可单字或批量写 |
| `+E0` | RW shadow | 本次系数设计采样率 Fs，整数Hz，非零，上电编译时INPUT_RATE_HZ |
| `+E4` | RW shadow | 本次系数设计截止频率 Fc，整数Hz，非零，上电1000 |
| `+E8` | RO | 生效设计采样率 |
| `+EC` | RO | 生效设计截止频率。自定义模式为主机声明值，不是FPGA测量结果 |
| `+F0` | RO | SOS API ID=`0x534F5301` |
| `+F4` | RO | 上传状态，见下表 |
| `+F8` | RO | 配置生效序号；每次成功 apply 加1，U32回绕；上电0，软复位/clear不清零 |
| `+FC` | RO | 当前滤波入口实际采样率 |

`+F4` 含义：

| bit | 含义 |
|---|---|
| 0 | 当前 active 是自定义系数 |
| 1 | 最后接受的 commit 快照是自定义系数；pending=0时也保留，不表示仍在提交 |
| 2 | 与 STATUS.bit2 相同，commit pending |
| 3 | 当前上传中至少一个系数字已写入 |
| 4 | 当前上传的阶数开始命令已写入 |
| 5 | 30个系数字全部完整写入 |
| 31:6 | 0，保留 |

成功 apply、soft reset、clear 后 bit3/4/5清零；影子银行数据仍保留可读。读取系数区得到的是 **shadow**，不能把它作为正在运行的 active 银行。提交后以 `pending=0`、生效序号变化、`+64/+E8/+EC/+24` 和错误状态核实结果。

## 4. 系数编码和打包

每个系数是 signed48 二进制补码，46个小数位：`real = integer / 2^46`。数值范围为 `[-2, 2-2^-46]`；1对应整数 `70368744177664`、48位十六进制 `0x400000000000`。不得截断/回绕超范围系数。

先把4节×5系数依次连接为120字节，再切成30个U32。每个signed48使用6个小端字节，**没有填充字节**：

```text
SOS0.b0, SOS0.b1, SOS0.b2, SOS0.a1, SOS0.a2,
SOS1.b0, ...,
SOS2.b0, ...,
SOS3.b0, SOS3.b1, SOS3.b2, SOS3.a1, SOS3.a2
```

一节占30字节，因此奇数编号节不是U32对齐的独立结构。不要给每个48位系数分配两个32位寄存器；本接口采用连续紧凑格式。

例如连续系数c0/c1编码后：`word0=c0[31:0]`，`word1={c1[15:0],c0[47:32]}`，`word2=c1[47:16]`。每个word通过VLP1按U32小端传输。

Python打包：

```python
payload = b''.join(v.to_bytes(6, 'little', signed=True)
                   for section in sections_q46 for v in section)
words = [int.from_bytes(payload[i:i+4], 'little')
         for i in range(0, 120, 4)]
assert len(words) == 30
```

C++应先把有符号数转成 `uint64_t`，再提取最低6字节，避免负数右移和符号扩展差异：

```cpp
uint64_t bits = static_cast<uint64_t>(coefficient);
for (unsigned b = 0; b < 6; ++b)
    payload.push_back(static_cast<uint8_t>((bits >> (8*b)) & 0xff));
```

## 5. 正常配置流程与事务语义

推荐首版上位机使用“暂停对应采集通道后应用”流程，沿用现有Qt控制顺序，尤其不要在DLIA禁用期间让ADC持续向其FIFO写入。

1. 识别 `+F0`，读取当前使能、输入实际采样率 `+FC`、序号 `+F8`、错误状态。记录本路ADC/DLIA使能状态。
2. 禁用对应ADC采集、等待排空，再禁用/clear对应DLIA和采集FIFO。不要对ADC0发软复位，以免复位共享双通道ADC PHY。
3. 若更改ADC采样率，先按ADC协议提交并回读实际值，再计算本次滤波系数。两路ADC的共享时序约束仍适用。
4. `WRITE_REG BASE+60, count=1, flags=0, [N]`，开始上传。重复写此寄存器会清空完整性位图，需要重传所有30字。
5. `WRITE_REG BASE+E0, count=2, flags=0, [Fs,Fc]`。
6. `WRITE_REG BASE+68, count=30, flags=0, words[0:30]`。所有请求逐一等待ACK成功。**不要使用 AUTO_COMMIT**；完成全部字段和回读后单独提交。
7. READ_REG回读阶数、设计Fs/Fc、全部30字及`+F4`，比对发送值；检查bit3/4/5全部为1。
8. 保存提交前的`+F8`；写CONTROL=4（当前禁用）或5（保持启用）。同一次不得混入soft reset/clear。
9. 轮询STATUS.bit2到0，并验证`+F8`增1、active阶数/Fs/Fc、profile、自定义状态bit0和错误增量。**WRITE ACK只表示接受commit，不表示已经生效。**
10. 恢复DLIA和ADC原使能，等待滤波建立后再使用结果；记录本次配置和生效序号。

若保持采集在线，所有影子写入不影响当前运算；提交接受时冻结完整快照，处理完旧周期流水后，在下一采集周期的首样本前切换。pending期间禁止写新增滤波寄存器、系数银行和旧截止频率寄存器。原参考频率/相位等普通shadow仍按原约定允许为下一次提交预写。

禁用时等待流水空闲后生效；启用但没有新的采集周期时，pending可以一直保持。超时上位机应读回状态并选择暂停/清理流程，不能自动重发commit。clear/soft reset会取消pending和本次上传标志，保留当前active配置；之后必须重新从写`+60`开始上传。禁用、复位或重新连接后的ACK不确定也按回读恢复，不能假设写事务具有回滚或幂等保证。

在线生效不等于USB旧队列已排空：旧周期的数据帧可能在commit ACK之后才到达主机。当前payload不含配置序号，也没有新增生效周期号寄存器；需要严格归属配置的记录，应使用暂停、排空/清理和分段记录流程，不得用“收到ACK的主机时间”直接区分新旧参数数据。

只修改输出率、参考频率或相位时，不写新的滤波开始命令和系数字，普通commit会保留当前自定义滤波器。回到内置模式时写`+60=0`后commit，或者写`+58`合法档位后commit；即使截止档位值与之前相同也能退出自定义模式。

## 6. FPGA检查与错误恢复

自定义commit需要阶数开始标志、30字完整性、合法阶数、正确一阶节位置和单位填充节。所有4节按量化后的整数系数检查以下严格不等式（`ONE=2^46`）：

```text
ONE + a1 + a2 > 0
ONE - a1 + a2 > 0
ONE - a2      > 0
```

这是实系数二阶分母的Schur/Jury单位圆稳定条件；等号（单位圆上的极点）会拒绝。FPGA不验证系数是否真是Butterworth，不验证声明的阶数与传递函数约消后的数学阶数相同，也不验证Fc与真实频响一致。以上属于主机设计校验责任。

还要求 `Fs == 当前实际输入率`、`Fc > 0`、`2*Fc < Fs`。commit接受后、等待生效期间实际输入率变化，会取消此次生效、保持旧active、置ERROR.bit8；序号不增加。自定义active运行时输入率改变，会停止接收新样本并置bit8，避免用错误采样率解释结果。恢复时暂停采集，清理残留队列，按新实际率重新设计上传后恢复。

| 场景 | 结果 |
|---|---|
| 阶数1/9、非法Fs/Fc、缺少系数字、奇数节形状错误、不稳定分母 | commit或字段写拒绝，ERROR.bit4置位，active不变 |
| 系数字节选通不是4'hF、未开始上传就写银行 | 拒绝，需按完整字上传 |
| pending中重复commit | 原cfg错误码8；旧快照继续等待生效 |
| 写只读寄存器 | 原cfg错误码6 |
| 非4字节对齐访问 | 原cfg错误码5；VLP传输层也会检查对齐 |
| 系数非法/不完整、设计率失配的commit | cfg错误码7；运行时率变化则通过ERROR.bit8报告 |
| 参数范围/写入策略错误 | cfg错误码7；银行pending写拒绝为8 |

错误位为粘滞历史状态。应读写前后增量并在确认处理后W1C，不能把旧错误直接当成本次失败。线上的返回状态采用已有cfg到VLP映射，详见主协议，不是把4位cfg错误码当完整VLP status。

## 7. 数值设计、增益与动态行为

参考生成器在 [host/dlia_filter_coefficients.py](../../host/dlia_filter_coefficients.py)。依赖NumPy/SciPy，采用SciPy Butterworth设计，先排列二阶节（低Q在前），奇数阶的一阶节最后；随后逐节归一化为单位DC增益、量化并重新检查稳定性与可表示范围。

不能直接将SciPy默认SOS各行乘2^46后发送：默认增益集中在首节，其余节分子可能含2，超出signed Q2.46正数上限，且低截止频率高阶首节分子可能过小。必须先做逐节增益分配。不要仅按“启用更多节”复用四阶系数；每个阶数对应不同极点/Q值，需要重新设计整组。

每节内部状态为signed48、16小数位，乘积96位、累加100位，按现有规则四舍五入（半值远离零）并饱和。每节输出回到signed32再送下一节；系数量化、节间舍入和非线性饱和都会影响实际误差。稳定极点检查不保证任意输入幅值无饱和，也不消除定点极限环。

参考生成器的系数量化使用Python `round`（最近值，半值取偶），随后按整数DC和修正b1；这是离线系数生成规则，与RTL样本算术的半值远离零分别定义。其它语言移植时应按示例整数及测试向量核对，不能仅比较浮点打印值。

四节流水相较旧两节增加6个100MHz时钟（60ns）的算术延迟，维持原输入吞吐约束和样本tag传递；滤波群延迟取决于阶数/Fc，通常远大于几十纳秒。参数真正改变时清空全部历史，带来启动瞬态；相同配置重提交保持历史。正常扫描边界不清空历史。数据时间戳仍为原采集tag，不补偿群延迟。

这里触发清历史的变化是系数、阶数、内置/自定义模式或自定义设计Fs/Fc。单独改变MODE.bit2旁路、参考相位或输出率仍沿用旧行为，不自动清滤波历史；旁路时算术历史继续更新。需要从零状态开始时使用clear/soft reset并重新上传/提交。

Fc的合法数学范围不等于已验证的工程适用范围。接近0时需检查量化精度、极点和建立时间；接近Nyquist时需检查系数范围/响应。还要结合抽取后输出率评估抗混叠：`Fc < 输出率/2`只是基本要求，不能替代完整过渡带/阻带评估。参考生成器遇到不能表示/不稳定的设计直接报错，不裁剪系数。

## 8. 可复现示例

在仓库根目录生成三阶、1.25kHz、1MS/s配置文件（只生成文件，不访问USB）：

```powershell
python -B host/dlia_filter_coefficients.py --sample-rate 1000000 --cutoff 1250 --order 3 --channel 0 --output E:/Documents/Vapor_Lc_App_Test/dlia_filter_example.json
```

对应Q2.46各节为：

| 节 | b0 | b1 | b2 | a1 | a2 |
|---|---:|---:|---:|---:|---:|
| 0 |1080924166|2161848333|1080924166|-140182657331223|69818236850224|
| 1 |275257891917|275257891917|0|-69818228393830|0|
| 2 |70368744177664|0|0|0|0|
| 3 |70368744177664|0|0|0|0|

生成文件含30个32位word；开头三个为 `406D9806, 300D0000, 000080DB`。写入序列为 `0x5060=[3]`，`0x50E0=[1000000,1250]`，`0x5068=words[30]`，回读成功后独立写`0x5004=4/5`。

在Python调用 `generate_dlia_filter(Fs,Fc,N)` 返回定点系数与words；`register_writes(design,base)` 返回上面前三个WRITE操作，**不包含commit和使能操作**，以便上位机先回读、处理失败和保留通道原状态。完整VLP帧、CRC和ACK匹配沿用现有主机协议实现。

## 9. 上位机交付检查项

- 支持API探测、自定义profile、2～8整数阶和整数Hz输入，使用实际Fs设计。
- 每次完整上传先写阶数；5系数/节、6字节/系数、无填充、共30字；保证系数符号一致。
- 写失败不commit；commit后验证pending、生效序号和active元数据；超时不自动重发。
- 断连、复位、采样率改变时重新识别和回读；两路分别管理配置，遵守共享ADC约束。
